## 2026-10-09 文本调用等待超时

按用户确认，车泰斗文本调用恢复为每次最多等待 5 分钟，响应头与正文接收均计入总等待时间。收到网关超时响应或本地等待超时后中断本次连接，Call 收尾为 FINISHED/PROVIDER_FAILED，关联维度为 FAILED，任务按结果聚合为 FAILED/PARTIAL；接口下发 `errorCode=PROVIDER_TIMEOUT` 和中文提示「等待超时，请重试。」。已成功维度保留，用户可通过原重试接口手动重试失败目标，不自动重发收费请求。

本地中断不能保证上游模型已停止；超时分支不扣费、不假定免单，Call 的 billingStatus 留为 REVIEW 供费用核对。没有新增环境变量、接口或数据库结构。本节覆盖下文“慢响应持续等待”中取消本地超时的历史规则；普通网络中断仍按原逻辑待核对，历史无回执的调用不自动改写或重发。

## 2026-10-09 内部分隔符与闭合符修复

保留正常 JSON 解析及原有完整结构格式修复；原完整性检查拒绝时，仅接受 `jsonrepair` 在字符串之外、回复内部插入 `,`、`}`、`]` 的候选。原文每个字符必须保留，不接受删除/替换字符、修改字段和值、在回复末尾补结构或字符串。修复日志记录 Call ID 及插入位置、字符；候选重新通过 JSON 解析后，继续原阶段结构与业务校验，坏选项仍逐条剔除。

此规则覆盖下文仅修复已闭合结构的历史范围，可挽救相邻选项缺 `},` 等错误，不扩大为内容补写。未结束字符串、缺值、截断数字、回复末尾缺闭合符仍拒绝；不新增模型调用，不修改原始回执或历史失败任务，不追扣已判 FREE 的调用。新执行修复后的有效结果按现有结算规则处理。

## 2026-10-09 选项辅助字段缺失容错

按用户确认，批量扩展、单维扩展/刷新及发散不再仅因缺失 `dependentChanges`、`incompatibleWith` 而剔除选项，解析副本补为 `[]`；`requiresEvidence=false` 时缺失 `evidenceNeeded` 同样补为 `[]`。原始模型回执不改写，模型输出要求仍保留完整字段。已返回的错误类型、证据标记缺失、需要证据时缺少说明，以及核心字段、文案、选择覆盖等校验继续生效。

本节按用户要求调整 PRD 必填字段在服务端的处理方式，不新增模型调用、接口或数据库变更。新执行时容错后有效结果按现有规则结算；不自动恢复历史失败维度，不追扣已判 FREE 的调用。

## 2026-10-09 模型输出数量要求

新任务提示词版本为 `a1-20261009-json-parse-check-v15`。识别必须按任务冻结的 `dimensionCountRange` 输出维度，每维扩展、刷新及发散必须按 `optionCountRange` 输出新增选项，上下限均含边界；例如 10–20 维必须至少 10 维、最多 20 维，选项范围按每维单独计算。提示词删除“数量仅作目标、允许不足”的宽松要求；输出前在原调用内部数清有效且不同的项，不足时继续补充合法内容，超过时筛选至范围内，再核对完整 JSON。识别请求的 `outputSchema.groups` 同时提供本次数量的 `minItems`/`maxItems`。

格式自检明确要求以 `JSON.parse(完整待输出文本)` 或等价严格解析器为标准，解析失败则修正后重新检查完整输出，并专门禁止字段冒号错写为逗号。本次有代码执行工具时才要求实际执行解析；当前文本请求没有提供此工具，提示词不能保证模型真正运行解析器，服务端解析与结构校验仍保留。旧任务继续使用冻结模板。

按用户确认，后端不增加数量不足/超出的失败条件：仍逐条剔除不合格与重复内容，保留实际有效结果，不因清理后少几项而整批失败。原有结构/业务失败、无有效结果及计费规则保持；本次不增加模型调用或自动付费重试，不修改历史任务快照、已生成结果或已判免费的调用。提示词与自检不能保证模型每次严格遵守数量。本节覆盖以下历史说明中模型侧“数量仅作目标”的要求。

## 2026-10-08 本地挽救模型输出

文本输出正常解析失败时，复用已有 `jsonrepair` 在本地修复一次格式，再执行原阶段结构与业务校验，不新增模型调用。仅修复已闭合的对象或数组；未闭合容器/字符串、缺值、省略占位或截断数字不补写为成功结果，必填业务内容不由修复器生成。

识别请求的 `outputSchema` 按任务冻结的文字模式生成：keep/translate/hide 仅允许 visual；show 要求包含 copy；hide 禁止 copy_layout。实际识别回复先剔除非 show 的 copy 及 hide 的 copy_layout，再校验剩余维度；必需文案/货篮覆盖、唯一维度标识和其他业务规则仍保留。清理后没有可用维度则失败，不按空结果成功结算。

批量扩展、单维扩展/刷新和发散改为逐条执行选项 Schema 与既有业务校验，剔除坏项后保留合格项。同名保留首个合格选项，复用 key 的后项剔除，不改写标识或补写文案。数量仍为生成目标；没有可用选项时该维度/调用失败。批次缺少或重复目标维度、options 不是数组等整体结构错误仍失败。

原始模型回执保持不变，修复和清理日志记录 callId、原数组位置、删除数量与原因，选项日志另带 dimensionKey（适用时）。已有 Call 原请求不改写，历史已判 FREE 的调用不追扣。产品计费规则保持：本批仍有任何失败维度则整批免费，成功结果保留；全部成功才走现有实际账单结算与幂等扣费。无需接口、数据库或依赖变更，原提示词分阶段及最终自检继续生效。

## 2026-10-08 联想返回前最终自检

自检在原模型调用内完成，不增加模型调用或自动付费重试，后端校验继续保留；不保证模型每次都能自检正确。已有 Task 提示词快照及 Call 原请求不改写，无接口或数据库结构变更。

## 2026-10-08 联想识别与选项扩展分阶段

识别结果校验并保存后，按最多三维一批生成各维度的选项，数量取任务冻结的 `optionCountRange`；扩展模板保持原文。已有 Task 提示词快照及 Call 原请求不改写，前端接口和数据库结构无需变更。

## 2026-10-08 组织提示词使用已有结果

COMPOSE 不再要求整轮联想全部成功、必需维度齐全或等待“换一批”完成，可直接使用当前有效选择组织提示词。其他维度失败、待核对或重试中均不阻塞；`allowPartialIdeation` 保留兼容，但不再控制是否放行。无需数据库变更。

保留来源有效性、草稿 revision、模型就绪、选择及输出校验。组合冻结提交时的选择；后续维度刷新应用若改变当前草稿，原组合仍按现有版本规则失效，使用新结果需重新组合。本节覆盖旧文档中的联想完整性及必需维度组合门槛；前端不应再因整轮状态或刷新中禁用“组织提示词”。

## 2026-10-08 待核对联想中的失败维度可独立重试

`POST /tasks/:id/retry` 对 IDEATION 且显式传入 `groupIds` 的请求按所选维度校验：根任务为 FAILED/PARTIAL/WAITING_RECONCILIATION/RUNNING 时，明确 FAILED 且自身原调用已确认的维度可以重试，不因其他维度待核对而被拦截。成功、运行中或 UNKNOWN 维度，以及自身原调用仍为 SUBMITTING/WAITING/UNKNOWN 的失败维度均不可重发。整轮无 `groupIds` 的重试和其他文本任务保留原整链核对门槛。

重试沿用原快照，仅执行所选失败维度；不同失败维度允许并行重试，无整轮串行限制；维度条件更新防止同一维度重复提交。每笔重试独立收尾，根任务按全部维度汇总，其他维度仍在执行时保持 RUNNING。其他未知调用与成功产物保持不变；重试完成或取消后，只要仍有未知维度，整轮继续显示待核对。现有失败维度按钮与请求格式无需调整，无数据库变更。本节覆盖旧说明中定向联想一律检查整条根任务未知调用的口径。

## 2026-10-08 按模型开启 JSON mode

参数与原请求一起落库并计入 requestHash；旧模板没有 JSON 关键词时，新 JSON mode 调用补充格式指令。已有 PREPARED/已提交 Call 保留原请求，不因启用 JSON mode 追加调用或重发。此规则仅作用于车泰斗文本执行器，不修改其他业务、图片请求、接口或数据库结构；网关能力变化后再更新已核验模型名单。

## 2026-10-08 慢响应持续等待，待核对结果自动恢复

车泰斗所有文本模型沿用同一处理流程：取消本地请求的 5 分钟中断及 HTTP 响应头/正文等待超时，保留原连接直到回复或连接明确失败。正在本进程执行的任务不因更新时间过旧被标记为待核对。原回复返回后立即保存完整回执、requestId 和用量；数据库暂时不可用时保留原回复并重试保存，不重新生成。

每分钟自动核对 `WAITING_RECONCILIATION`：已有完整回执的调用按原快照重新校验、恢复维度选项/任务产物、更新草稿引用及聚合状态，并沿用原 Call 幂等结算。只恢复收到回执的批次，其他未知批次保持待核对；无效 JSON 收敛为明确失败，不伪造成功、不新增付费修复。识别结果恢复后可以继续尚未提交的扩展阶段。

网关 SDK 0.14 的文本 Chat 没有按 requestId/幂等键查询或重放结果的契约，用量查询只提供账单。旧调用已经断开且没有完整回执时，这次后端修改无法找回文本；服务重启或上游断连后要保证最终回复可恢复，仍需网关提供持久化文本异步任务及结果查询/回调。接口和数据库结构不变。

旧冻结模板和已发请求不改写，旧响应的扩展检查不保存到新组合输出，也不因逐字不一致失败；明确的硬事实冲突仍不能进入 READY。既有失败任务不自动恢复，不新增自动付费修复，前端接口无需修改。该说明覆盖原 2026-10-07「产品硬条件传递」扩展及本次未部署的 v6 组装方案。详见 [修复说明](./README.compose-constraints.md)。

## 2026-10-08 自动联想统一单选，自建维度由用户指定

AI 自动联想的全部维度统一 `selectionMode=single`，覆盖所有文本模型；后端在识别结果入库前规范化该字段，模型返回多选、遗漏或填错选择模式均按单选处理。旧维度的详情接口同样返回单选，换一批的新组和任务快照使用单选；组合提交对自动联想维度按单选校验，已有选项和该维度自填方案合计最多选择一项。旧草稿已选择多项时需要重新选择，不自动替用户删除选择或修改历史记录。

用户新建维度仍通过 `customDimensions[].selectionMode` 指定 `single` 或 `multi`；保存、DIVERGE 生成选项及应用后保留用户的模式，单选最多选一项，多选可选多项。任务详情、列表的 `groups[]` 新增 `selectionMode=single`，维度详情的 `definition.selectionMode` 同口径；前端自动联想维度按单选渲染，自建维度保留单选/多选设置，无需数据库迁移。

## 2026-10-08 同名选项去重

联想批量扩展、单维扩展/换一批、自建维度发散的模型选项按名称去除首尾空白后去重，保留首次出现的完整选项与原顺序，再入库和展示；同名重复不再直接导致整个维度失败。不同名称复用同一 key 仍拒绝。Call 原始回执保留，不改写历史任务状态，前端无需配套改动。

## 2026-10-08 数量作为生成目标，优先保留成功结果

用户确认：维度数、每维选项数及去重后的数量不符合目标范围均不作为失败条件，按实际数量保存、展示和标记成功；适用于新任务及旧冻结任务的后续执行。原来要求 30–60 项而实际仅生成 6 项时，保留 6 项，不裁剪、不凑数、不追加付费调用。空数组同样按实际零项返回，结构与必需业务维度校验保留。

新提示词版本 `a1-20261008-json-contract-v9` 继续要求合法 JSON、必填字段和合理内容，并将数量明确为目标。刷新和旧任务组合不再要求至少十个成功维度；未知调用、字段缺失、选择标识歧义和真实业务冲突仍按原规则处理。成功结果按现有账单结算，既有失败/免费记录不自动改状态或追扣。接口字段不变，前端使用实际 `groups.length`、`optionCount`、`newOptionCount` 展示。

## 2026-10-07 失败免扣、待核对按账单扣费，不自动付费重试

本节覆盖下文及旧方案中的“一次修复预算”和失败调用计费说明。模型超时、格式错误、限流均不自动重试付费请求；新快照的修复预算固定为 0，历史快照中的预算和旧环境变量也不能开启自动修复。用户可以手动重试明确失败的维度，UNKNOWN/待核对调用仍不可重发。

文本正常完成后结算；明确失败免扣费，`UNKNOWN` 或已提交且所属任务为 `WAITING_RECONCILIATION` 的待核对调用仍按实际账单扣费。后台查账同时处理成功和待核对调用，账单迟到进入 `REVIEW` 后继续查询；无账单保持待结算，不估算扣费、不记免费，也不重发模型。正常运行中尚未校验的结果不提前扣费，明确失败在事务内再次拦截，重复查账沿用原 Call 幂等键。批量联想以模型调用为计费单位：同批任一维度失败，整批免扣费，已成功的维度保留；识别维度调用在全部成功后结算，任务待核对时同样参与查账；明确部分失败/失败时尚未扣除的识别费用免扣，已判免费的历史调用不追扣。独立成功批次正常结算，手动重试仅对新成功调用结算。

图片生成失败或取消免费，即使网关返回成本账单也不向用户扣费；待核对图片查询原网关任务，有实际账单则按既有一口价/按量规则结算，不重新生图；转存失败维持待交付，恢复原图片成功后才与结果保存一起结算。历史已扣积分不自动退款。本次无需改表，前端接口不变。

## 冻结的冲突结构

```ts
interface Conflict {
  id: string
  questionVersion: number
  question: string
  reason: string
  sources: string[]
  choices: { id: string; label: string; instruction: string }[]
  blocking: boolean
}
```

上述字段均返回；数组允许按语义为空（sources 必须非空）。所有问题和选项展示文本为中文。提交 `{conflictId: conflict.id, questionVersion: conflict.questionVersion, choiceId: choice.id}` 或自由 `text`，一次提交全部非阻断问题，同一问题不能重复提交。blocking 问题不提交答案，通过修改草稿解决；存在阻断时建议前端先引导修改输入。提交答案幂等键重用时返回原任务，不因指针已推进而产生 409。

## 拆解补充字段（P1-6）

- `basketContents.hasItems: boolean|null`：true=有物品，false=明确空，null=无法判断；旧导入稿可能整个 basketContents 为 null，也必须显示未知。
- `baskets?: {id,position,hasItems:boolean|null,evidence,items:string[]}[]`：每个可辨认货篮一个元素。存在多个货篮时不强行合为一个。联想针对有物品的篮子用 `purpose=basket_contents` 和 `basketId` 明确对应对象。
- `pets/props: {id,description,position}[]`：模型新拆解提供；旧稿未记录时返回空数组，前端可回退软特征文字，不据空数组宣称图片中绝无该对象。
- 新 JSON 字段兼容冻结的旧任务/旧拆解，无需全量重新调用模型。真实有物品的篮子必须有对应变化维度，未知不能按空篮生成建议。

创建时仍查询模型参数配置并校验质量、编辑操作和参考图等非尺寸参数，批量任务冻结请求，幂等与计费流程不变。新任务冻结 `normalizationMode=CROP_ONLY`。交付始终检查图片实际比例，允许单像素取整误差：符合目标时保留原始字节，不符时按中心最大范围裁剪，不额外缩放或补档。局部重绘目标比例取源图比例，清晰度优先继承来源任务。旧快照的 `NONE` 标记也不再跳过比例检查，已保存成品不自动重裁。

原图和成品仍按原有路径分别保存，保留失败恢复逻辑、字段和访问权限。VidFlow 继续复用相同服务，接口和调用参数不变，无需修改前端或 Prisma Schema。
