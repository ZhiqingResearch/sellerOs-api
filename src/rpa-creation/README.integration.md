# 内部创作：用户文案调整（2026-10-14）

适用于「内部图片/视频创作 Workspace」和「内部批量 Workspace」。接口仍为 `/api/rpa-creation/*`，字段名、模型编码、状态枚举、扣费规则及上传目录不变。

## 前端同步

消费项 `source=rpa-creation.generate` 的中文展示名改为 **内部创作**。
请在前端 `src/lib/billing/usage-item-label.ts` 更新旧中文名对应的映射，英文建议使用 **Internal Creation**。
后端接口路径、筛选 value 和其他字段均不需要调整。

任务进度、任务/输出失败原因与接口错误响应采用中性文案，例如：

| 场景 | 文案 |
| --- | --- |
| 参数准备完成 | 参数已准备，正在提交生成任务 |
| 提交完成 | 已提交，排队生成中 |
| 提交或重试提交失败 | 提交失败，请稍后重试 |
| 生成、缺失输出或结果转存失败 | 生成失败，请重试 |
| 生成或重试超时 | 生成超时，请重试 |

上游原始失败原因保留在服务端日志，不透传给前端。模型展示名已检查，无需调整；项目默认名称仍为「未命名项目」。

## 部署与历史数据

正常部署并重启服务即可，无 Schema 变更。注册表初始化会将该 source 的旧名称「影刀 RPA 创作」/「影刀RPA创作」改为「内部创作」，只更新 label，不修改 active 或其他配置；重复启动可安全执行。新环境初始化和静态兜底使用同一新名称。

历史积分明细通过 source 实时解析展示名，不需要逐条修改流水。历史任务和输出中的旧供应商文案在所有任务返回入口统一映射，不批量改写任务记录，也不处理用户输入的提示词或自定义项目名。

验收时覆盖提交、失败、超时、重试、历史任务详情/列表，以及积分明细和消费项筛选。此次后端验证使用单元测试与构建，真实生成流程仍需前后端联调。
