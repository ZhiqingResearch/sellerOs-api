# 视频预估报价前端联调文档

更新日期：2026-10-12。

继续使用 `POST /api/ai-models/quote`，只传模型、业务分类和当前模式/分辨率，即可查询单位积分。无需提示词、视频时长或素材。普通视频显示“积分/秒”，前端自行乘秒数；按次收费的模型显示“积分/次”。

**本次契约调整：`*_credits` 和 `*_amount` 从整次生成的总价改为单位价格，新增 `billingUnit` 标明单位。前后端需同步发布，旧前端不能继续把返回值直接当总积分。** 生成、上传、任务查询和实际扣费沿用现有流程。

## 请求

先通过 `GET /api/ai-models?modality=VIDEO&category=NORMAL` 获取可用模型，使用返回的 `publicId`，按 `facts/requestSchema` 渲染模式和分辨率选项。禁用或网关不可用的模型继续隐藏，补成本不会重新启用模型。

```http
POST /api/ai-models/quote
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
  "category": "NORMAL",
  "publicId": "sourcing-seedance-mini-i2v",
  "params": {
    "mode": "image_to_video",
    "resolution": "480p"
  }
}
```

| 字段 | 要求 |
| --- | --- |
| `category` | 必填，当前业务分类，如 NORMAL、REFERENCE、MOTION_CONTROL、STORYBOARD、BEAUTY |
| `publicId` | 必填，当前可用模型列表中的 ID |
| `params` | 必填对象，自适应且无需模式时可传 `{}` |
| `params.mode` | 模型有模式选项时传当前模式；省略时只匹配通配模式档 |
| `params.resolution` | 有分辨率选择器时传当前分辨率；自适应模型按能力省略 |
| `params.prompt`、`params.duration_seconds`、素材等 | 报价不需要；兼容旧请求传入，但不参与单位报价计算 |

正式生成仍需按生成接口要求提交提示词、时长和素材。报价成功只表示匹配到了价格，不代表完整生成参数已校验通过。

内部接入的 `POST /api/internal/generation/models/quote` 同步采用以上请求及响应，沿用原内部鉴权。

不指定分辨率时，本地成本报价可以返回多个分辨率的 `variants`。前端有分辨率选择器时应传入当前选项，不能用价格档位代替模型能力目录。

## 响应

以下为成本 0.784～0.833 元/秒、模型倍率 1.5、对应一口价为空时的单位报价：

```json
{
  "object": "pricing.estimate",
  "model": "sourcing-seedance-mini-i2v",
  "operation": "videos.generations",
  "currency": "CNY",
  "pricing_version": "local-video-unit-costs",
  "expires_at": 1791763200,
  "variants": [
    {
      "parameters": {
        "resolution": "480p",
        "mode": "image_to_video"
      },
      "estimated_amount": null,
      "minimum_amount": "1.176",
      "maximum_amount": "1.2495",
      "estimated_credits": null,
      "minimum_credits": "11.76",
      "maximum_credits": "12.495",
      "billingUnit": "SECOND",
      "exact": false,
      "route_dependent": false,
      "pricingMode": "metered",
      "assumptions": ["本地成本单位预估（积分/秒），实际按网关账单结算；区间使用最低/最高积分展示"]
    }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `billingUnit` | `SECOND`：积分/秒；`REQUEST`：积分/次；没有成本配置时为 `null` |
| `minimum_credits/maximum_credits` | 单位积分上下限，十进制字符串或 `null` |
| `estimated_credits` | 单位积分；成本上下限相同时有值，区间时为 `null` |
| `estimated_amount/minimum_amount/maximum_amount` | 同一单位的人民币售价，已乘模型倍率，尚未做积分取整；不是原始成本 |
| `pricingMode` | `fixed`：匹配一口价；`metered`：本地成本预估，实际按网关费用结算 |
| `exact` | 一口价为 `true`；成本预估为 `false`，即使上下限相同也不承诺最终扣分 |
| `assumptions` | 单位说明或无法预估的原因 |
| `pricing_version` | 本地成本为 `local-video-unit-costs`，一口价为 `fixed-unit-credits`；作为不透明版本字符串处理 |
| `expires_at` | Unix 秒时间戳，当前取响应生成时刻；不要因此立即循环刷新 |

报价已包含“成本 × 10 × 模型倍率”，前端不要再乘 10 或 1.5。倍率读取数据库 `priceMultiplier`，配置为 1.5 时即按 1.5 计算。

## 前端展示与总积分计算

默认展示单位价格，例如“预计 11.76～12.495 积分/秒”。积分字符串保留原有精度，不要先把每秒单价取整。

| 类型 | 单位价格示例 | 5 秒的总预估 |
| --- | --- | --- |
| 按秒固定成本 | 3.45 积分/秒 | ceil(3.45 × 5) = 18 积分 |
| 按秒区间成本 | 11.76～12.495 积分/秒 | ceil(11.76 × 5)～ceil(12.495 × 5) = 59～63 积分 |
| 按次成本 | 141 积分/次 | 141 积分，不乘秒数 |
| 按秒一口价 | 15 积分/秒 | 15 × 5 = 75 积分，不再乘倍率 |

`pricingMode="metered"` 且 `billingUnit="SECOND"` 时，前端按每个上下限分别乘有效秒数后向上取整。使用十进制运算，避免浮点误差导致整数边界多取 1 分。按次成本报价已经向上取整，直接使用即可。一口价按返回单价乘数量，保持精确值，不额外加倍率或取整。

仅展示单位价时不需要时长；时长尚未选定时可保留单位价，不展示总积分。总积分指单次生成的预估，批量任务应逐任务估算后合计。按量预估旁显示“实际消耗以任务结算为准”。

下面示例仅负责选择和展示单位报价，可直接用于页面：

```ts
type QuoteVariant = {
  parameters: { resolution?: string; mode?: string }
  estimated_credits: string | null
  minimum_credits: string | null
  maximum_credits: string | null
  billingUnit: "SECOND" | "REQUEST" | null
  pricingMode: "fixed" | "metered"
}

function selectQuoteVariant(variants: QuoteVariant[], resolution?: string): QuoteVariant | null {
  const key = resolution?.trim().toLowerCase()
  if (key) {
    return variants.find(v => v.parameters.resolution?.trim().toLowerCase() === key) ?? null
  }
  return variants.length === 1 ? variants[0] : null
}

function formatQuoteCredits(variant: QuoteVariant | null): string {
  if (!variant?.billingUnit) return "暂无法预估"
  const { minimum_credits: min, maximum_credits: max, estimated_credits: estimated } = variant
  const unit = variant.billingUnit === "SECOND" ? "秒" : "次"
  const prefix = variant.pricingMode === "fixed" ? "" : "预计 "
  if (min != null && max != null) {
    return `${prefix}${min === max ? min : `${min}～${max}`} 积分/${unit}`
  }
  return estimated != null ? `${prefix}${estimated} 积分/${unit}` : "暂无法预估"
}
```

所有积分都为空时显示“暂无法预估”，不能按 0 分处理；字符串 `"0"` 则是有效价格。多档响应应按当前分辨率选中对应项，不能直接使用第一项。

## 按次模型与原有档位

原 57 档的模型、分类、模式和分辨率保留，精确模式优先，通配模式补缺。Seedance 参考模式保留 `mode=''` 通配档；视频编辑应显式传 `video_to_video`。

- Seedance 视频编辑的 480P、720P 成本分别保存，可独立调价，当前返回 `REQUEST`。
- Kling O3 自适应编辑成本按次，返回 `REQUEST`。
- 其他按秒成本返回 `SECOND`，前端根据单位决定是否乘秒数。
- 禁用 Grok 继续不在模型列表中出现，直接请求报价返回 404。

`costMinCny/costMaxCny/costPerRequest` 是后端配置，不直接下发。`costPerRequest` 标记成本的元/次或元/秒口径，并决定成本报价的 `billingUnit`；不参与实际扣费。若配置了有效一口价，一口价优先，单位跟随该一口价档位。

## 刷新与错误处理

分类、模型、模式或分辨率变化时重新查询；只改时长时前端重新计算总积分，只改提示词时无需重查。数据库成本更新后，下次报价立即使用新值；重新进入页面或重新选择模型时刷新即可，不做持续轮询。

切换配置时清除旧报价，用请求序号或参数快照丢弃晚到的旧响应，避免旧价覆盖新选择。

| 情况 | 前端处理 |
| --- | --- |
| 积分与单位为空 | 显示“暂无法预估”，不认定为免费或模型不可用 |
| 401 | 使用现有登录过期处理 |
| 400 | 展示后端参数校验 message，保留表单供修改 |
| 404，模型不存在或未启用 | 清除失效选择，刷新模型列表 |
| 502，视频预估成本配置无效 | 展示 message，联系后端检查成本配置 |
| 网络失败 | 清除旧价格，允许重试 |

异常响应为 `{ statusCode, message, timestamp }`，`message` 可能是字符串或字符串数组。

报价不创建任务、不冻结或扣除积分。页面建议使用“预计消耗”，不要写“已预扣”。余额准入和最终扣费以后端生成及结算流程为准，不能仅用预估与钱包余额比较后禁止提交。任务终态后刷新钱包和消费记录；按量任务失败但有实际费用时也可能扣费。
