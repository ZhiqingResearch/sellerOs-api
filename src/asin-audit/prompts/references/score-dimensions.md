## 3.3 统一计分规则（A / V / E 三分母）

三个量由**服务端**重算，模型不输出聚合分：

| 符号 | 含义 |
|---|---|
| **A** | 适用满分 = 100 − 已判 N/A 的项目满分 |
| **V** | 有效证据满分 = A − 待核项目的满分 |
| **E** | 有效得分 = 已核验项目的实得分之和 |

```
已核验部分折算分 = 100 × E / V        （V = 0 时不评分）
证据覆盖率       = V / A
项目实扣         = 该项目已核验适用满分 − 实得分   （每项扣到 0 为止）
```

**只有全部适用项目都已核验（V = A），才能称"完整最终分"**；否则一律标注为「已核验部分折算分 · 证据覆盖率 x%」。**证据覆盖率 < 60% 时不出总分。**

六种数据状态的处理：

| 状态 | 判断条件 | 执行规则 |
|---|---|---|
| **完整取证且满足** | 检查点有明确、适用的证据 | 按检查点给分；连续比例项目按冻结公式算，不让模型自由猜分 |
| **确认缺失/不满足** | 相关页面或后台字段已完整取证，内容确实没有或不满足 | 按规则扣对应分值 |
| **待核/未校准** | 无权限、抓取不全、变体不明、缺竞品基准、或数值刻度尚未冻结 | **得分留空（score=null, status=pending）**；权重保留在 A 中，不计入 V。**禁止默认为 0 或满分** |
| **N/A 不适用** | 有明确的品类 / 产品 / 业务证据支持不适用，并记录原因 | 从 A 与 V 中同时剔除；**不能用 N/A 掩盖缺数据或规则未定** |
| **计算错误** | 满分/得分缺失、NaN、分母为 0、解析错误 | 阻止发布该分数，先修数据；不能把异常强制转 0 |
| **问题去重** | 每个问题保存唯一 owner 项目 | 同一规格冲突归 F；首页只归 G1；机会词自然曝光只归 G3；集中度只归 J2。只有独立缺陷才能分别扣分 |

其他口径：购买展示档位（300+ / 100+ / 400+）只是展示信息，**不作为固定加分项**。三种规则状态：**沿用** = 有上次执行锚点；**补充细化** = 本次补足操作方式；**待校准** = 尚不能数值评分。

## 4. 诊断话术与问题条目

板块得分（百分制）= round(Σ该板块已核验项目实得 / Σ该板块已核验项目满分 × 100)；域得分 = round(Σ(板块得分 × 板块总分) / Σ板块总分)，内容域分母 64、运营域分母 36。等级：≥85 优秀 / ≥70 良好 / ≥50 一般 / <50 待优化（由服务端计算）。

每个项目失分时 deductions 必须写扣分原因，格式：`扣 N 分 · 当前 x/max（完成度 y%）· 具体原因与证据`。

诊断话术（每域一段，≤3 句，输出到 diagnosis.contentNarrative / operationsNarrative）：

```
这条 Listing 的{域名}整体 {域得分} 分（{等级}），证据覆盖率 {V/A}。
{域得分≥85 时补一句：基本盘扎实——{最高板块名} 等板块已达标；}
当前最该先修的是{最弱板块}（{分数}分）：{问题一句话}，{对业务的影响}。
{次弱板块<85 时：其次{次弱板块}（{分数}分）也需跟进。}
{存在待核项目时：{板块名}的 {项目名} 因{原因}判待核，未计入本次折算分。}
```

问题诊断条目（diagnosis.issues，取最弱的 ≤3 个板块，每板块 1 句总述 + 2 条带证据的具体问题）：

```
{板块名} {分数}：{总述}
  · {证据句 1 —— 必须含具体数值与所属项目 ID}
  · {证据句 2 —— 必须含具体数值与所属项目 ID}
```

证据句参照（数据从证据卡取，不许编）：
- 「F1 六组核心事实：RAM 组标题写 16GB、参数页写 8GB，属确认矛盾，整组扣 2 分」
- 「G1 固定核心词池 12 词，当日观测到自然首页的只有 4 个，命中率 33%，扣 8×67% = 5.36 分」
- 「J2 合并同义词族后，最大词族占自然曝光 62%；假设该词族归零，剩余仅 38%，低于 60% 韧性线 22 个百分点，扣 2.2 分」
- 「A2 冻结的 6 项核心意图里，"降噪强度"与"佩戴稳固"两项权重合计 35% 全页未表达，扣 4×35% = 1.4 分」
- 「H2a 当前评分 3.9★，低于 4.0，扣 2 分；评论数量不参与判定」
