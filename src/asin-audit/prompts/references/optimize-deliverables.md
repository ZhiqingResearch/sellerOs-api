# 优化交付物逐项写作规范（references/optimize-deliverables.md）

本文件定义优化环节各项交付物的字段约定与写作细则。所有内容须基于证据（A/P/B/C/D/E 六卡）与十板块扣分，**针对此 ASIN**，禁止套模板空话。

---

## ① 优化后 Listing 本体（`listing`）

### 标题 `listing.title`
- 按目标站点语言；把 S 级词（月搜索量最高的品类核心词）放在**标题可识别位置（主体段）**，覆盖 A 级词（不得写"前 80 字符"——该门槛已取消）。
- 若 A 卡有原标题，围绕其失分点重写（补核心词 / 场景词 / 差异卖点），不要凭空另起。
- **埋词去重**：原标题已覆盖的语义不必重复堆砌；新增词优先补「标题尚未覆盖语义」的核心词，同 / 近义表达只保留一个。
- 控制长度合规（Amazon ≤200 字符，建议 ≤150；简洁优先）。

### Bullet `listing.bullets`（数量由诊断决定）
- 每条以 `**[大写标签]**` 开头（如 `**[48H ULTRA-LONG BATTERY]**`）。
- 每条包含**可验证数据点**（dB / 小时 / IPX / 克重 / 认证）。
- **尽量每条对应一个竞品差评痛点或一个失分维度**，可在文本中用"针对…"体现回应关系。
- 覆盖 COSMO 关系：功能（USED_FOR_FUNC）、受众（USED_FOR_AUD）、场所（USED_IN_LOC）、能力（CAPABLE_OF）、兼容对象（USED_ON）。

### 产品描述 `listing.description`
- 分 3–4 段，段头可用 ALL CAPS 小标题；覆盖使用场景（USED_IN_LOC）、兼容设备（USED_ON）。
- 融入品牌背书 / 工艺数据，正面回应高频差评。

### 后台搜索词 `listing.searchTerms`
- 数组，每项为一个词/短语；**先过「禁词红线」三类过滤**（促销词 / 他人型号裸写 / 竞品品牌词，兼容前缀表述除外）。
- **不与标题、Bullet 已用词重复（语义重复也算重复）**；标题已覆盖语义的词改埋到标题后，多余的同义词才进这里。
- 补机会词、长尾词、目标市场语言的同义词（降 CPC）；总字节尽量接近但不超过 249 字节；过滤后无合格词可为空。

### Q&A `listing.qaCandidates`（数量由诊断决定）
- 抢占 Rufus 引用，主动回应高频疑虑（结合 B 卡差评与常见买家顾虑）。
- 答案以 Yes./No. 或具体参数事实开头，1–2 句，可验证、不夸大。

## ② 图片卖点建议（`imageSellingPoints`，按 E1 缺失检查点逐项补，不设张数及格线）

每条 `{ type, name, description }`：
- `type`：如 `主图` / `副图1`…`副图6`。
- `name`：图片主题（如"核心卖点拆解图"）。
- `description`：拍摄/设计要求 + 要标注的数据/文案，须回应差评或强化差异化。

推荐组合（按需针对本品调整）：
1. 主图：纯白底产品图（占比≥85%，合规无水印）
2. 信息图：3–4 大核心卖点拆解（配数据）
3. 场景图 A：主用户场景实拍
4. 场景图 B / 痛点回应图：针对高频差评正面回应（实测数据）
5. 对比图：与竞品在关键维度并排对比
6. 尺寸/适配图 或 规格表图
7. 包装清单图：强化"完整套装 + 质保"信任感

## ③ A+ 页面模块方案（`aplusModules`，数量自定，E2 只出建议）

每个 `{ name, nameEn, description }`：
- `name` 中文模块名，`nameEn` 英文标签（如 `Brand Story` / `Comparison Chart`）。
- `description`：模块内容与目的（回应差评 / 强化差异化 / 促转化）。

标准 6 模块：品牌故事横幅、核心卖点四宫格、竞品对比表、使用场景图文、规格参数表、FAQ + 售后保障。

## ④ 核心关键词分层词库（`keywordTiers`，tier 枚举 S/A/B/longtail）

四组 `tier` 依次为 `S` / `A` / `B` / `longtail`，每组 `{ tier, label, keywords[] }`：
- `S`：月搜索量最高的品类核心词 —— label「标题可识别位置」
- `A`：次高频精准词 —— label「标题 + Bullet 1-2 必现」
- `B`：中长尾词 —— label「Bullet 3-5 + 描述覆盖」
- `longtail`：机会词 / 同义词 —— label「后台搜索词兜底」
- 词一律来自 D 卡反查词 / C 卡竞品词 / 机会词清单，不得编造。
- **禁词过滤**：先过三类禁词红线（促销词 / 他人型号裸写 / 竞品品牌词，兼容前缀表述除外），命中不收；过滤后无合格词该层留空。
- **埋词去重**：S / A 层只收 A 卡标题尚未覆盖语义的词；标题已有同 / 近义表达的词降入 B 层（Bullet / 描述）或 longtail 层，并在建议中注明改埋位置，不得为凑数重复塞标题。

## ⑤ 评论响应策略（`reviewStrategies`，覆盖 B 卡 Top 痛点）

每条 `{ painPoint, response, improvement }`：
- `painPoint`：B 卡 Top 差评痛点（引用真实痛点文本与频次）。
- `response`：可直接发布的官方回复模板（引用实测/认证数据正面回应）。
- `improvement`：闭环改进动作（如新增说明书、Vine 定向测评、A+ 增加实测图表）。
- B 卡未取证时，基于通用买家顾虑给 3 条，并在 `improvement` 注明"（证据缺失·通用建议）"。

---

## ⑥ 差异化 USP 提炼（`differentiationUSPs`，数量由诊断决定）

每条 `{ title, analysis }`：
- `title`：USP 名称 + 类型（如"48H 真续航（验证型 USP）"）。
- `analysis`：为什么是差异点 —— 引用 C 卡竞品对比（竞品平均值 / 竞品自然占比）+ B 卡 VOC（差评出现频次）+ 建议放置位置（标题/Bullet/A+）。

---

## ⑦ 投放节奏建议（`launchPhases`，按产品阶段给）

三阶段 `name` 依次为 上新期 / 成长期 / 成熟期，每个 `{ name, timeline, goal, tactics[] }`：
- `timeline`：周期（如"第 1–4 周"）。
- `goal`：阶段目标（如"打基础 · 攒评论"）。
- `tactics`：3–5 条可执行动作（索评、广告结构、否词、ACoS/TACoS 目标、自然单占比目标等）；涉及「开启投放 / 调整出价」的动作遵守「广告建议闸门」——先看该词 D 卡 `ranking` 广告位，`广告无排名` 才建议开投 / 调价。
- 结合 E 卡经营数据与第⑧维流量结构给出针对性节奏（如广告依赖度高则成长期重点降依赖）。

---

## ⑧ 字段改写依据（`fieldRewrites`，6–10 条）

每条 `{ field, original, rewritten, reason }`：
- `field`：字段定位，如 `Title` / `Bullet 1` / `Description` / `Search Terms` / `Q&A 1`。
- `original`：引用 A 卡原文片段；若原字段缺失，写 `（原字段缺失）`。
- `rewritten`：可直接复制的改写文本，应与 `listing` 中对应内容一致或为其核心片段。
- `reason`：≤30 字，说明补了什么关键词、数据点、COSMO 关系或差评回应。

---

## ⑨ 改进优先级（`improvementPriorities`，数量由失分项决定；F1/F3 事实矛盾必须 P0）

每条 `{ level, title, impact, effort, action }`：
- `level`：`P0` / `P1` / `P2` / `P3`，按优先级从高到低排列。
- `title`：动作标题，如「重写标题主体段覆盖 S 级词」。
- `impact`：影响判断（高/中/低），可附带影响指标（CTR/CVR/自然排名/Rufus 回答能力）。
- `effort`：执行难度或耗时（低/中/高，或“5 分钟/半天/一周”）。
- `action`：清晰可执行动作，避免只写“优化 Listing”。
