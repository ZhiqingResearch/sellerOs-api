- 已核对实际数据库为 `agent-api-dev3`，内省当前 118 个 model，diff 确认仅 `CreditTransaction` 增加 `invokeType ENUM('PLATFORM','API') NOT NULL DEFAULT 'PLATFORM'` 后执行 `db push --skip-generate`。没有同步其它漂移；原 917 条流水及 ID 范围 1–920 保持不变。
- 部署说明已补充共享扣费依赖检查。补列后、仍采用旧固定费规则时，已用真实服务及数据库验证任务创建、20 积分流水和 UsageLog 写入，然后强制回滚；用户 3 前后余额均为 5305.867，积分批次及记录数量保持不变，未调用外部服务。检查脚本为 `scripts/check-category-analysis-database.ts`，复用前须核对已更新其旧固定费断言；不将该事务验证冒称当前实际 AI 计费或完整取数／报告已跑通。

## 最新计费指令与本次退款状态

- 创建任务、取样本和补充类目数据不扣固定费用。未调用 AI 就因 SIF 配额不足失败，积分为 0；不能声称取数步骤消耗了 AI 积分。
- 每笔真实 AI 账单按实际模型售价倍率与既有公共计费规则结算，沿用个人／企业／邀请共享路由和生效折扣。每笔账单有独立的 `requestId` 幂等及 UsageLog；多个类目、一次格式重生成可以产生多笔账单，同一账单重试不能重复扣费。
- 没有真实账单就不按 token 或估价扣分，不能把未知账单成本填成已确认金额。外部数据服务人民币成本未取得，不合并伪装成 AI 用量成本。
- 已产生真实 AI 费用后，后续步骤失败保留已经发生的实际费用；报告保留成功部分。此规则与退还旧固定收费分别处理。
- 前端失败费用行按后端字段：`refundedCredits > 0` 才显示已退回的金额；否则 `credits > 0` 显示实际净扣；两者为 0 则提示未扣积分。旧记录缺少退款字段不推断已退款，终态刷新实际余额。
- **本次旧固定 20 积分退款已执行并核对**：开发库任务 #3／用户 #3，原流水 #922，新退款流水 #924 原个人 RECHARGE 桶返还 20，余额 5285.867 → 5305.867。原错误消费分类校正 MANUAL_ADJUST、保留原金额／原 type 元数据及退款关联，累计消耗纠正；任务及 UsageLog 净 credits 为 0，refundedCredits 为 20。再次只读检查 already-refunded，未重复返还。
- 新计费实库验证创建 0 扣费、模拟已确认账单 0.12 元按公共计费扣 2 积分、同账单重复处理不二扣／不二累加，最后全部强制回滚且无外部请求。后端相关 277 项、前端页面 21 项通过，后端构建和改动 ESLint 通过。浏览器已核对真实退款提示与取消固定价的新确认卡；SIF 配额仍限制完整报告验收。
